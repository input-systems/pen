# Collaboration Contract

Yjs converges, but convergence is not the whole answer once real users share a document. This document owns what Pen guarantees when more than one person is editing: how remote edits are labeled, how presence is validated, where authorship comes from, what happens when structural edits collide, and what Pen explicitly does not do. It governs origins and awareness in `packages/crdt/yjs`, `packages/extensions/multiplayer`, attribution in `packages/extensions/snapshots`, the normalization rules in `packages/core`, and `packages/transport`.

## COL — Collaboration contract

- COL1. Every update entering through `applyUpdate` is `origin: "collaborator"` unless the caller supplies a more specific structured origin; `"user"` means this client's user, always, and is never the default for an unlabeled transaction. The classification is proven through a real two-client sync — two adapters, one provider seam, updates crossing in both directions — rather than by passing an origin string to a transaction, asserting three properties: commit events on the receiving client report `collaborator`, the receiving client's undo stack is unchanged by remote edits, and suggest mode's origin bypass and input rules do not fire on remote content. A structured origin from a peer is a label for local reasoning and never a capability: nothing in Pen grants a peer behavior because of an origin the peer chose. Code below the commit event that observes raw Yjs transactions — the field-editor backends' `Y.Text` observers — classifies by the same rule: a transaction with `local === false`, or with a structured origin of type `collaborator`, is a collaborator edit, and origin strings are never compared.
- COL2. Awareness is an untrusted input boundary handled exactly like paste and import — one validator owns the whole payload and runs on receipt, before any peer state reaches a controller, a decoration, or the ledger — and invalid or over-limit state is dropped for that peer with a `presence-rejected` diagnostic naming the reason, so a hostile peer degrades to invisible and never to a broken document. The bounds are named constants with documented defaults in `packages/extensions/multiplayer/src/presence/constants.ts`: receivers accept at most `MAX_PRESENCE_UPDATES_PER_SECOND` (30) awareness updates per peer per second and senders coalesce local presence writes to a `LOCAL_PRESENCE_MIN_INTERVAL_MS` (50 ms) minimum interval so a well-behaved sender stays under every receiver's cap, alongside caps on user id and display name length, avatar URL length (and the avatar URL also passes `pen.urlPolicy`), serialized anchor length, offsets, block ids per remote selection, total awareness bytes per peer, and peers tracked per document — beyond the peer cap, additional peers are counted and not rendered. A peer's `user.color` lands in a CSS custom property on every viewer, so it is admitted only through a closed grammar (`isSafeCssColor` in `@input/pen-core`): a hex colour, a CSS named colour from a fixed list (plus `transparent` and `currentColor`), or `rgb`/`rgba`/`hsl`/`hsla` whose single argument list holds only digits, `.`, `-`, `%`, `,`, `/`, spaces, and `deg`; anything else — `url(`, `image-set(`, `var(`, `expression(`, comments, escapes, `;`, `}` — falls back to the assigned palette colour. The sinks validate again where they write `--pen-peer-color` (the overlay's caret and label styles, the React table cell ring) and paint it through `background-color`, never the `background` shorthand, so a value that reached the variable still cannot become an image fetch. Cursor and selection payloads are validated against the document rather than only against types, so a `blockId` that does not exist, an offset outside the block, or a cell outside the named block's grid is rejected at ingest instead of filtered later at render time, and Pen declares a closed set of top-level awareness keys — `user`, `cursor`, `selection`, `streaming` — each with a payload shape validated on receipt, while keys Pen does not declare are ignored rather than rejected, so a host may carry its own presence data that Pen never interprets as long as it does not reuse a declared name. `streaming` is the whole of what a peer can see of someone else's AI run: the generated text is a local decoration that never enters the document (RS1), so `{ blockId }` naming the block being written is the entire payload, published from the run's stream commits and cleared when it ends, and a receiver renders it as a block-level presence rather than as content. A local presence write merges into the awareness state instead of replacing it, because one extension writing its key wholesale silently unpublishes every other extension's. A remote cell selection is bounded by the live grid rather than by a constant: ingest rejects a row or column outside the named block's grid, and because a commit can shrink that grid under a held selection, resolve re-reads it and clamps the endpoints in, which is the AS3 treatment applied to a peer's coordinates instead of the local caret's.
- COL3. The Yjs `clientId` is the only identity the document actually contains: an opaque session number, not a user, not stable across reloads, and not attributable on its own. Anything Pen presents as authorship — blame ranges, character attribution, version snapshot authors, presence labels beside a caret — resolves identity through the host's resolver, whose contract is explicitly a trust boundary mapping `clientId` to an identity the host has verified against its own session, token, or user table; with no resolver configured Pen shows the `clientId` placeholder it already generates and never a peer-supplied display name. Peer-asserted names remain available only for live cursor labels in a session the host has not authenticated, documented as unauthenticated in the same sentence as the API, and they never feed attribution or a persisted snapshot, because a blame view renders a verified name and a claimed name with identical confidence and forged attribution is worse than absent attribution.
- COL4. The structural convergence matrix is enumerated and tested one scenario per row, at two, three, and five peers under fixed delivery schedules, each asserting that every peer reaches an identical document after normalization repairs have been exchanged and that the row's named outcome holds. Concurrent splits of one block each copy the text after their own offset into their own new block, because the executors move content by copy (AN14): splits at the same offset leave the head once and one copy of the tail per splitting peer (`["Hello", "World", "World"]` at two peers, n copies at n), splits at different offsets leave the head up to the earliest offset and each split block holding the text after its own offset, so text after the latest offset appears once per concurrent split that moved it and no character is lost, which is a Yjs semantic stated rather than fixed. Deleting a block against typing into it lets the deletion win and loses the typed text; deleting a block against moving it lets the deletion win and leaves no entry behind; moving one block under several parents leaves it under the parent whose id sorts lowest and present exactly once; a parent cycle across any number of blocks converges with the cycle broken by rule; concurrent indent and outdent converge to one parent; and overlapping reorders converge with no duplicate order entries after repair. Cycle prevention is a normalization rule with a deterministic tiebreak rather than a heuristic: when a block's parent chain reaches itself, the edge whose owning block id sorts lower is cleared — and when one block owns two edges of the cycle (its `parentId` and an entry in its `children`), the edge whose child id sorts lower — so every peer computes the same repair from the same state without coordination, whichever block of the cycle the pass reaches first, and the repair emits a diagnostic; a cleared `children` edge re-homes the detached block at the end of the root order, and the duplicate entries that peers repairing concurrently append are removed by the same pass once the repairs meet. An order or children entry whose block no longer exists is removed by the same pass with a `dangling-block-reference` diagnostic, because a concurrent move re-inserts the entry a concurrent delete removed; an entry counts as dangling only when the blocks map holds a deletion for its id (`CRDTAdapter.isBlockDeleted`), because out-of-order delivery can land an order entry one client wrote before the block map another client wrote, and removing that entry would leave the block in no array when its map arrives — such an entry is skipped like a dangling one and kept, and an adapter without `isBlockDeleted` treats every absent block as deleted; remote commits do not normalize, so such an entry survives until the next local pass or load, and until then core's iteration APIs (`editor.blocks()`, `blockCount()`, `firstBlock()`, `lastBlock()`, `documentState.blocks`, `blockCount`, `preorderBlockIds()`) and renderers skip it, so no handle for a missing block is ever handed out and range commands never name it in a `delete-block`; the remote commit that deleted the block still reports it `block-removed` in its summary, at the position it held, because the surviving order entry means no array edit names it and a commit that names nothing leaves every renderer drawing the dead block. Because remote and undo commits do not normalize, each hands the ids it placed, re-parented, created, removed, or deleted — read from its delta and change summary — to the next local commit's pass, whatever that commit edits, which runs the structural rules (duplicate entries, cross-array membership, dangling entries, the cycle break) on exactly those ids: a cycle, duplicate entry, or cross-array membership that only a remote commit creates is repaired by the next local edit on any peer, without `normalizeAll` and without a reload, and the duplicate entries concurrent repairs append are themselves remote commits, so the following pass removes them. A live block that such a commit leaves in no order or `children` array — a repair that removed one of its entries meeting a peer's concurrent move that removed the other — is appended to the root order with an `orphan-block-rehomed` diagnostic; only ids an external commit touched are checked, so a local edit is never re-homed. The structural pass reads liveness and membership from the index it already builds, so none of these repairs adds a document read (SCALE2). Structural invariants — no cycles, no orphans, no duplicate entries, no cross-array membership, no dangling entries — are asserted by `assertStructuralInvariants` from `@input/pen-test` after every schedule, the fuzzer runs at three peers on every pull request, a second property runs random concurrent moves, deletes, inserts, and indents at two to five peers with only the per-commit pass normalizing (never `normalizeAll`) and asserts convergence, every invariant, and that every live block is reachable, and its generator emits split, move, indent, delete, and nested-parent ops rather than text edits alone.
- COL5. Pen provides no transport, provider, server, persistence, rooms, or presence infrastructure: the Yjs adapter and the multiplayer extension consume a host-provided provider, and the reference app's WebSocket wiring is a demo and is labeled one. Pen authenticates no one and enforces no per-user or per-block permissions — there is no session, token, or trusted peer anywhere in the library, and a peer that can write to a room can write to the whole document; `pen.ariaReadOnly` sets `aria-readonly` and nothing else, the renderer `readonly` prop is what declines local typing and gestures, and neither is a security boundary, because `editor.apply` consults neither and gating incoming updates would break convergence, so access control lives entirely in the host's transport layer. Pen does not merge document schemas between peers — DUR3's preservation is what makes a staged rollout survivable — and contributes no queue, backoff, or conflict UI to offline editing, which is Yjs's guarantee and the provider's documentation; all of this ships together in the docs, because "read-only" reads like a guarantee and every item corresponds to a question an adopting team asks in its first week.
- COL6. Every published transport package declares in its README's first section which of three grades it is: reference (illustrates the protocol, not for production), production (documented guarantees, tested), or development-only (in-process, no network); a transport package without a grade line fails the doc gate. A transport that advertises a capability implements it or removes it — stream resume is implemented against a real, host-supplied history store, or the client stops sending `Last-Event-ID` and the README states that a dropped connection restarts the stream — because answering your own request with a "not implemented" status is a contract the package wrote against itself. Whatever the grade, the client validates: parsing runs inside a guard, unparseable events are dropped with a diagnostic, and event size is capped, so a malformed frame from a proxy or a truncated response cannot throw out of a stream iterator into host code; auth is a documented seam where the client accepts headers and the server handler names where a host inserts verification, and what the package must never do is imply that verification exists.

## Retired

No `COL` member is retired. COL1–COL6 are all live. One surface element was renamed rather than a rule retired: the facet named in COL5 became `pen.ariaReadOnly` because the previous generic name invited a guarantee it never made.
