# Reliability And Testing

Reliability here is a property of the test system as much as of the product: a gate that cannot fail, a target that cannot be met, and a gate that asserts a narrower property than its name claims all read as green on a dashboard. The testing tiers are pure unit and package-contract suites in Vitest on Node; a conformance layer driving Playwright against real Chromium, WebKit, and Firefox for DOM truth (selection reading and projection, gesture windows, IME, geometry, bidi, overlays, the `beforeinput` map, and perf budgets); a fuzz layer over random interleavings, seeded and bounded in PR CI and randomized nightly; and product-flow end-to-end specs that give integration sanity and never own a contract on their own. Logic that needs a real `Selection`, composition, or layout belongs in the conformance layer and never in a jsdom shim, because jsdom cannot represent selection geometry, `beforeinput` semantics, EditContext, IME, or layout. A normative rule ID is claimed by a test carrying that ID in its name; CH11 records which rules are claimed and stops a claim from silently disappearing, and a rule that is untestable as written gets the spec fixed rather than the test skipped.

## CH — Code health and test-system gates

- CH1. Zero `// @ts-nocheck` in the workspace. `@ts-expect-error` is allowed only with an adjacent comment naming the tracked issue, and the gate counts both directives and fails above the committed budget, whose target and default are zero.
- CH2. ESLint exists and runs: one flat config at the repository root, every package's `lint` script is `eslint .`, and the root ESLint script is a single repo-wide `eslint .` pass rather than a task-runner fan-out, which would double-lint packages and skip root files. The custom rules other rules depend on — no new slots, no HTML injection sinks, no deep imports into Pen packages, focus visibility, no above-floor API without an allowlist entry, no ASCII word boundaries, no bare case folding, no implicit locale — are plugins on this host, so any rule whose enforcement is a lint rule depends on this one.
- CH3. No placeholder tests: a skipped suite or test (`.skip`, `.todo`) must have a non-empty body and a comment naming the tracked issue and what restores it, and an empty skipped `describe` body fails the gate. Playwright's conditional `test.skip(condition, reason)` is a runtime browser filter rather than a placeholder and is ignored by the gate.
- CH4. No untyped mixin composition: object-literal method bags typed `this: any` and assembled onto a prototype are banned, as is the mechanical numbered-part file-split pattern. Files are split along domain seams into typed modules, because a size-motivated split that loses types is worse than the long file it replaced.
- CH5. Runtime packages report failures through the `diagnostic` event channel rather than `console.*`. Console calls are allowed only in the default diagnostics sink and in explicitly named debug modules, which are the documented exceptions rather than a general allowance.
- CH6. No orphan packages: every directory under `packages/` that the workspace glob reaches has a manifest and sources, or it is deleted. Build debris such as a stale `dist/` or `node_modules/` never ships as a package skeleton.
- CH7. The undo stack is bounded: `undoExtension({ maxDepth })` exposes the cap with a default of `DEFAULT_UNDO_MAX_DEPTH` (500), enforced in the Yjs adapter's undo-manager wiring, which trims the oldest undo and redo stack items when a new item is added past the limit. Unbounded history growth under streaming AI writes is a leak, not a feature.
- CH8. Blocking perf budgets do not share a runner with the parallel test suite and are judged on a central statistic — the median of a stated sample size — rather than a tail one such as a 95th-percentile figure over 100 iterations. `@input/pen-bench` runs in a dedicated serial job outside the parallel test task, a budget that cannot be met reliably on the CI runner is re-baselined with the new number written down rather than left permanently red, and tail latency stays visible as a recorded trend because it is real but is not something a PR gate can attribute to a diff. Before attributing a benchmark number to the code under test, the harness is run with that code removed and the floor recorded, and a target the floor already exceeds is rejected rather than reported as a regression.
- CH9. The suite gives the same answer twice: a test that fails on an unchanged tree is fixed or quarantined, never re-run. Quarantine is explicit — an allowlist naming the test, the tracked issue, and what resolves it — is reported, and is never silent retries, so `retry` in Vitest config is banned; determinism is measured rather than assumed by running the affected suite ten times on an unchanged tree and requiring the same failure set every run, and with an explicit `testTimeout` set, a test consuming more than half of it on an idle machine is too slow to be a gate input and is fixed or moved to the conformance layer. An entry leaves quarantine when the test passes on an unchanged tree, or when an equivalent assertion lands in a real-browser scenario and the jsdom copy is removed in the same change — deleting the assertion is not a third exit — and when duplicate suites covering one rule are merged, the surviving file must first absorb every behavior only the other one pinned, so a falling test count is stated as which named tests duplicate which named survivors rather than left unaccounted.
- CH10. `pnpm lint` covers what its name promises, so the formatting scope is declared rather than implied: Prettier owns documentation, workflow, and configuration files, ESLint owns TypeScript and JavaScript source style, and the root manifest pins the source indentation convention so a stray formatter run cannot convert the tree. The format gate fails closed on a missing formatter binary and on an empty path list, because a glob that silently matches zero files otherwise reports success.
- CH11. Rule claims are checked rather than asserted: `scripts/rule-coverage.mjs` (`pnpm coverage:rules`, the `rule-coverage` repo gate) derives the live inventory from the `- ID.` bullets under `spec/rules`, `spec/charter`, and `spec/packages`, skipping Retired and Dropped sections and bullets marked retired, and reads test names from every Vitest, Playwright, and `node:test` file in the workspace. Every entry in the committed claimed scope (`scripts/rule-coverage-claimed.txt`) must have a test carrying that ID in its name; an entry that no longer names a live rule fails the gate (I15); a claim the scope does not record fails until it is recorded; IDs outside the scope are reported by name. File names do not claim a rule, `.skip`, `.todo`, and `.fixme` titles do not claim (CH3), and an ID two documents share is resolved by a `[selection]`/`[facets]` qualifier in the test title or by the test's package path (`scripts/rule-coverage-config.json`).

## Retired

No `CH` member is retired. CH1–CH11 are all live and block pull requests.
