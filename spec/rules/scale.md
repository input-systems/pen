# Scale Envelope And Anchor Performance

SCALE governs how Pen behaves as documents, extension stacks, and sessions grow: the envelope a host can design against, the cost of a single commit, what the benchmarks measure, memory over a long session, and the host-windowing contract. PG1 is the performance contract for anchors. Pen does not virtualize — a host that needs a larger document windows blocks itself, and SCALE5 is the contract for doing that correctly. Frame-level scheduling budgets belong to SCH in `spec/rules/dom.md`; the workloads, published envelope table, committed baselines, and gate scripts live in `packages/tooling/bench` (see `spec/packages/tooling/bench.md`).

## SCALE — scale envelope

- SCALE1. One published table states the tested envelope — block count, longest single block, nesting depth, table dimensions, and concurrent peers — alongside the browser support floor, and every cell is a number that a bench or conformance suite actually exercises. Every number carries its grade: verified (a suite asserts behavior at that size on every run), measured (a benchmark records it, with no pass/fail on the clock), or untested above (the honest ceiling). The table is derived from the suites rather than asserted independently, so raising a number means raising a fixture; it also names what degrades first past the ceiling and refers to SCALE5 rather than repeating it.
- SCALE2. The commit path's work is a function of the change, not of document size or extension count: for a single-character insert into a document of M blocks with N extensions installed, the work is proportional to the affected blocks, not to M, and not to N beyond a cheap per-extension interest check. Decorations are dirty-scoped — an extension declares which blocks its decorations depend on, defaulting to the commit's affected set, unaffected blocks keep their previous decoration set by identity, and decoration-set identity is stable when nothing changed — and an extension that declares no interest in a commit is not called. `JSON.stringify` is banned as a change-detection mechanism in per-commit and per-render paths; signatures come from the summary's identity and version counters instead. The gate is `pen/no-json-stringify-signatures` over `@input/pen-core` and the rendering packages; wire-format / display / clone sites live in `scripts/json-stringify-allowlist.json`.
- SCALE3. The benchmark set includes the configuration hosts ship: a keystroke in an envelope-sized document with a realistic extension stack, meaning the default preset plus AI, suggestions, autocomplete, search, and multiplayer as no-op-configured extensions. Each benchmark declares the single axis it isolates — document size, extension count, decoration count, remote-caret count — and the set covers each axis at two points, so a regression report can name the axis that moved. Baselines are committed per benchmark with the machine class that produced them and are updated only in a change that says why; benchmarks run in their own CI job, isolated from the parallel test run, and are compared against the committed baseline rather than against an invented absolute target.
- SCALE4. Every cache in a hot path declares its bound: a maximum entry count, a TTL, or a lifetime tied to a document or editor object, where a `WeakMap` keyed by a DOM node or an editor is a bound and needs no number. `editor.destroy()` releases everything the editor allocated — caches, indexes, decoration sets, undo stacks, field editors — and a standing assertion proves that a destroyed editor retains nothing. A nightly soak scenario (thousands of edits, undo/redo cycles, remote updates, AI streams, mount and unmount cycles) samples heap and reports it as a trend rather than a gate, with one hard assertion: heap after a full teardown-and-recreate cycle returns to within a stated multiple of the baseline.
- SCALE5. Pen does not window blocks and exposes no `virtualize` prop; a host that needs a larger document windows blocks itself. The contract is that any block holding neither the active field editor nor an active selection endpoint may be unmounted; while unmounted its document state is untouched and its decorations are computed but not rendered; selection targeting an unmounted block parks its projection without a diagnostic and projects when the scheduler next projects or a renderer acknowledges a mount, and `selection-target-unmounted` (level `warn`) is emitted once per record version only when the target's element is present and projection into it fails; and the host does nothing on remount, because reconciliation is idempotent. One conformance scenario exercises the contract end to end — window a large document, scroll it, edit inside the window, and move selection to a block outside it, asserting document correctness and the expected diagnostics — and the docs carry a minimal host-windowing example.

The published table is `packages/tooling/bench/ENVELOPE.md`, generated from `packages/tooling/bench/baselines/envelope.json`. It records block counts of 100, 1,000, and 5,000; a 100,000-character single block; nesting depth 10; a 50 × 20 table (1,000 cells); and 2 concurrent peers, with every axis untested above its top rung. Verification for the ladder is headless, and the concurrent-peer grade is survival of both inserts rather than peer-to-peer equality alone, because two independently populated documents can converge on the same lost `Y.Text`. Past the ceiling, per-commit decoration collection and full-document render degrade first.

The envelope is graded provisional: counts are the durable measure and fail on drift on every machine class, while the wall clocks were taken under load on `macos-arm64` and are compared only within a machine class, gated at `max(attributedP50Ms * 3, attributedP50Ms + 1)` for rungs whose attributed median reaches 0.5ms. The realistic-stack keystroke baseline `packages/tooling/bench/baselines/scale3.json` records a 0.04ms p50 at 100 blocks and 0.06ms at 1,000 blocks, with eight added no-op decorating extensions at 0.06ms, 256 decorations at 0.05ms, and eight remote carets at 0.06ms — the SCALE2 evidence that extension, decoration, and remote-caret count do not move per-keystroke cost. Remote-caret count is eight `data-pen-remote-caret` decorations on one editor, not N exchanging `Y.Doc`s, so N-synced-peer scaling stays unmeasured. `packages/rendering/react/VIRTUALIZATION.md` carries the host-facing form of SCALE5.

## PG — anchor performance contract

- PG1. Anchor cost is bounded on the 10k-word fixture: mint p95 ≤ 5µs per anchor, cold resolve p95 ≤ 1ms for 1,000 anchors resolved in one read phase, cached resolve (AN8) p95 ≤ 50µs for 1,000 repeat resolutions within one commit, repair (AN14) p95 ≤ 0.5ms for 1,000 live anchors on a structural commit, and the selection authority's per-commit resolution work adding ≤ 0.1ms p95 to commit-pipeline phase 6. Those µs and ms lines are recorded bounds rather than enforceable thresholds, because they are machine-dependent and encoding one as a CI threshold gates the runner instead of Pen. What is enforced is the count artifact `packages/tooling/bench/baselines/v3-anchor-budget.chromium.json`: `pnpm --filter @input/pen-bench run bench:anchors:compare` fails by name on a cardinality change, fails on a missing baseline, and fails on a zero-row file, so it cannot pass over an empty set.

The committed artifact records encode sizes of 4/6/6/6 bytes for `clientID: 0` only, mint at roughly 0.39µs, and 1,000 cold resolves in 0.15ms, with the harness floor subtracted. Those are Node figures rather than browser figures and the artifact says so; the Chromium scenario asserts the same cardinalities against `editor.anchors`. Cached resolve, repair, and the phase-6 delta remain unmeasured, which the artifact states rather than defaulting them to green. The count set includes a table-cell cohort because a cell's text is a nested `Y.Text` at `tableContent[row].cells[col].content` while a table block has no `content` key at all — a different substrate, not a size variant — and there is deliberately no cell analogue of the split benchmark, since splitting a table cell is a validated no-op.

## Retired

The `virtualize` prop on the renderer editor components, including its `mobileOverscan` option, is deleted. It was accepted and discarded, and an inert prop tells every consumer who reads the type the opposite of what SCALE5 decides.

The absolute µs and ms figures inside PG1 are retired as enforceable thresholds and survive as recorded bounds only; the enforced gate is the count artifact named in PG1.
