# Security Rules

The `SEC` family is the complete security posture for the workspace: nothing security-relevant ships outside these rules. The attacker-controllable inputs are pasted clipboard content, imported content, AI and tool payloads, and the document itself; host-provided configuration such as custom schemas, renderers, and facet values is trusted, because hosts own their own code. Because any peer with write access can place arbitrary strings into block props, mark records, and inline-node props through a raw CRDT update that never passes `editor.apply` validation, the load-bearing boundary is render and interaction time rather than import time — importers exist to preserve fidelity, not to establish safety. Pen guarantees that rendering arbitrary written state is safe; it does not implement content encryption, access control, or a permission model, which belong to the host and the transport.

## SEC — security model

- SEC1. One module owns URL admission for everything the library renders: `urlPolicy` in `@input/pen-core` (`packages/core/src/security/urlPolicy.ts`), re-exported by `@input/pen-dom` so renderer hosts keep their import path, with the shape `resolve(rawValue: unknown, context: "link" | "image" | "media" | "download") => string | null` where `null` means inert. The default policy admits `http:`, `https:`, `mailto:`, and `tel:` plus relative and protocol-relative URLs, admits `data:image/(png|jpeg|gif|webp|avif)` in `image` context only, and returns `null` for everything else including `javascript:`, `vbscript:`, `file:`, `data:text/html`, unparsable values, and non-string values; admission parses with `new URL(value, "https://pen.invalid/")` and compares the parsed protocol, never a regex over the raw string. A `null` resolution renders the element without its URL-bearing attribute plus `data-pen-blocked-url=""`, and the raw URL is never echoed into the DOM, logs, or diagnostics beyond its scheme; every URL sink in library rendering and export goes through the policy, including `htmlExporter`'s built-in image serializer and every `<img src>` in a schema `toHTML` result (a host override does not skip admission), and hosts customize it through the single-value `pen.urlPolicy` facet, which receives the default policy to delegate to, so loosening to arbitrary schemes is possible but explicit.
- SEC2. No library code turns a string into markup. The `no-html-injection-sinks` lint runs unscoped across every linted file in the workspace and reports assignment to `innerHTML` or `outerHTML`, any use of `insertAdjacentHTML` or `Range.createContextualFragment`, `document.write` and `document.writeln`, and the `dangerouslySetInnerHTML` JSX attribute; reading `innerHTML` stays legal because assignment is the sink, and all rendering builds DOM through `createElement`, `textContent`, and attribute setters. Parsing untrusted HTML into a detached document with `DOMParser.parseFromString` is permitted because parsing is not injection, but the parsed tree's text and attributes only ever enter the document as data and are never re-serialized into live DOM; model output is text by construction, flowing through `TextStreamWriter.append` or ops, so no path exists by which it becomes markup. Two helpers apply a decoration's attribute bag to an element and both carry the discipline: `applyElementAttributes` in `@input/pen-dom` writes inline decoration attributes, and `mergeBlockDecorationAttributes` in `@input/pen-react` (`primitives/editor/block.tsx`) turns block decoration attributes into props on the block host. Both skip every key matching `/^on/i` and every key that lowercases to `style`, because event handlers and stylesheets are not data. Their skip sets are deliberately not identical: a React prop name reaches sinks a DOM attribute name cannot, so the React helper also skips `dangerouslySetInnerHTML`, which `setAttribute` renders inert and a React prop does not. The URL-policy clause — `href`, `src`, and `xlink:href` admitted only through the policy, writing `data-pen-blocked-url=""` when admission fails — belongs to the DOM helper, whose callers render URL-bearing elements. The block helper omits it because no producer emits a URL-bearing key on a block decoration and the default host element is a `<div>`; `asChild` lets a host supply a URL-bearing element instead, so the omission rests on the absent producer rather than on the tag, and gaining such a producer means gaining the clause. The discipline lives in the helpers rather than in each caller's judgment, so a decoration that carries presentation in an inline `style` attribute has no effect and class hooks are the working contract for styling decorations. The rule names both helpers because naming one taught readers there was one: `@input/pen-multiplayer` emitted a `style` attribute on remote presence decorations for the colour, correctly inert on the DOM path and a thrown React `setValueForStyles` error on the block path that unmounted the editor's root the moment a peer selected a block. On a React prop this rule is a crash guard, not only a policy, and `no-html-injection-sinks` cannot stand in for it: that lint reads literal JSX attribute names and a key arriving through a spread is invisible to it.
- SEC3. HTML sanitization has exactly one owner, the `html` surface of `@input/pen-interop` (`packages/extensions/interop/src/html/import/sanitize.ts`), built on DOMPurify with an explicit tag and attribute allowlist, and no regex ever rewrites sanitized markup. Clipboard producers may express formatting in stylesheet classes, so before the final DOMPurify pass removes every `<style>` element, the sanitizer parses the detached source and resolves declarations from simple `.class` and `tag.class` rules onto matching elements. Complex selectors, at-rules, nested blocks, and escaped selectors are ignored; within the admitted subset, tag-plus-class specificity and source order apply, then inline declarations win. Both stylesheet and inline declarations pass the same closed filter, and the final DOMPurify `uponSanitizeAttribute` hook enforces it again on serialized attributes. `color` and `background-color` remain mark-bearing properties. `font-weight`, `font-style`, `text-decoration`, and `text-decoration-line` are admitted only for the closed keyword and numeric values the inline converter maps to bold, italic, underline, and strikethrough marks or explicit mark resets; unsupported, inherited, functional, escaped, or URL-bearing values are dropped. `text-align` is a document property mapped to the default text blocks' validated `textAlignment` prop, not a styling escape hatch: it is admitted only when the value is exactly one of `left`, `right`, `center`, `justify`, `start`, or `end` after trim and case-fold (a trailing `!important` is stripped and not re-emitted). Any other value — including `url()`, `expression()`, CSS comments, escapes, or unsupported multi-token strings — drops that declaration. The HTML `align` attribute is on `ALLOWED_ATTR` for the same reason, and the same hook keeps it only when the value is `left`, `right`, `center`, or `justify`. The list stays closed to properties the converter consumes. The config keeps `id` out of `ALLOWED_ATTR` because it is DOM-clobbering surface that conversion does not consume, and sets `ALLOW_DATA_ATTR: false` so no `data-*` wildcard becomes a markup-smuggling or exfiltration channel through round-trips. The paste path uses the same module — clipboard HTML goes `sanitizeHTML` → bounded `htmlparser2` conversion; when a browser host lacks `Object.hasOwn`, the HOST4 path uses detached `DOMParser` for the stylesheet pre-pass and conversion instead — `@input/pen-dom` transfer code must not parse raw clipboard HTML itself, and the sanitizer is a direct dependency of the package that owns paste conversion (`@input/pen`, which installs `html-clipboard`) rather than an optional peer, so it cannot be absent at runtime.
- SEC4. Copy writes `text/plain`, `text/html` (exporter-generated and escaped per SEC5), and `application/x-pen-blocks+json`; the older `application/x-pen-blocks` flavor may still be written so older readers keep working, and paste reads the current MIME first, then the legacy flavor. Pasted JSON and imported JSON documents are schema-validated before ops are built: block `type` must resolve in the registry, props are validated by the block's prop schema, unknown block types and unknown props are dropped with `diagnostic { code: "import-dropped" }`, and depth and node-count bounds are constants rather than options (nesting depth 32, 10,000 nodes per ingest, as `INGEST_MAX_NESTING_DEPTH`/`INGEST_MAX_NODE_COUNT` and their clipboard counterparts, which add a 1 MiB text cap and a 256-image cap). Every ingest path carries the same bound set rather than JSON alone — the JSON, HTML, Markdown, and XML surfaces of `@input/pen-interop` and the `@input/pen-dom` clipboard path each own named constants — and a drop caused by a bound reports `diagnostic { code: "import-truncated" }` to distinguish a size refusal from a content refusal. `__proto__`, `constructor`, and `prototype` are rejected as own keys anywhere in ingested JSON — props, marks, and metadata — ingestion builds fresh null-prototype records during validation rather than deep-merging raw parsed JSON into existing objects, and URL-bearing props are not pre-laundered: they pass through SEC1 at render time like everything else, so a policy change applies retroactively to stored content.
- SEC5. Exporters — the XML and HTML surfaces of `@input/pen-interop`, the HTML clipboard flavor, and any `toHTML` path — construct output through a serializer that escapes text nodes and attribute values (`&`, `<`, `>`, `"`, `'`), and interpolating unescaped document content into markup is banned by the `no-unescaped-markup-concat` lint over `packages/extensions/interop/src`, `packages/schema/src`, and the two `@input/pen-dom` clipboard serializers (`utils/clipboardSerialization.ts` and `utils/tableCellClipboard.ts`), which admits an interpolation only when it passes an escaping or serializing call, is already-serialized inner HTML, or is justified by an adjacent comment naming SEC5. Despite its name that lint inspects markup template literals only, so `+` concatenation into markup is not reported: the escaping obligation is the rule, and the lint covers the shape this codebase writes rather than the full obligation. The scope includes the block and inline `toHTML` serializers in `packages/schema`, whose sinks are attribute interpolations rather than text nodes (`href` on link marks, color values into `style`, image `src`, inline-node `data-id`, `class="language-…"` on code blocks): serializers receive the escaping helper (`packages/schema/src/escapeHtml.ts`) or emit structured nodes the exporter serializes, and never concatenate raw prop values into attribute positions. Export → sanitize → import is a round-trip property: a document carrying hostile-corpus strings as plain text yields the same plain text back with zero markup execution, and a document whose `href`, color, `lang`, or `data-id` props contain attribute-breakout strings exports to HTML that parses back with those values as attribute data and zero new elements or handlers.
- SEC6. `@input/pen-tools` validates tool-call payloads structurally before building ops: the op `type` must be a known member of the `DocumentOp` union, targets must resolve, and string fields are capped by a constant (`MAX_OP_TEXT_FIELD_LENGTH`, 1 MiB per op text field); an invalid payload produces diagnostics and no partial application. Ops arriving from any source cannot smuggle non-validated shapes past the pipeline's validate phase, whose unknown-type drop is the enforcement point and whose diagnostics are the audit trail. Op executors never spread raw payload objects into CRDT writes: the validate phase applies the same `__proto__`/`constructor`/`prototype` own-key rejection as SEC4, and executors build fresh records from validated fields.
- SEC7. Dependencies that process untrusted markup are limited to DOMPurify via `isomorphic-dompurify` and the `htmlparser2` / `domhandler` parser pair used by the bounded HTML and XML ingest paths; adding another such dependency amends this rule. DOMPurify's version range is pinned to a patch range (`~2.36.0`) so a security-relevant minor or major cannot arrive unreviewed. No published package may declare an install script — `preinstall` and `postinstall` are banned, checked by `scripts/no-install-scripts.mjs` — `pnpm audit --prod` runs in CI as a report and blocks a release cut on critical advisories in runtime dependencies, and dependency-update automation covering the workspace and its GitHub Actions, `dependency-review` on pull requests, and CodeQL or an equivalent SAST on the default branch keep a small dependency surface current rather than merely small. `SECURITY.md` carries the private disclosure channel, a 90-day coordinated-disclosure default, a supported-versions table, and a commitment to publish advisories for anything reachable through the SEC1–SEC6 surfaces; npm provenance (API7) is the control that makes those claims verifiable from outside the repository.
- SEC8. The library executes no dynamic code: `eval`, `new Function`, and string-bodied `setTimeout`/`setInterval` are banned by lint across all packages (`no-eval`, `no-new-func`, `no-implied-eval` in `eslint.config.mjs`), and Pen must be fully functional under `script-src 'self'`. Inline `style` attributes are used only for geometry-derived positioning such as overlay transforms and everything else is class-based, so a host running `style-src` without `'unsafe-inline'` loses only overlays; a strict-CSP conformance scenario documents exactly what degrades.
- SEC9. `@input/pen-search` treats a user-supplied regex as hostile input: `regex: false` is the default, query length is capped by a constant (`SEARCH_QUERY_MAX_LENGTH`, 1,024 characters), and a pattern compiles with the `u` flag inside a `try`/`catch` that surfaces an invalid pattern as a diagnostic rather than a throw. Regex execution runs under a budget: matching proceeds block by block with a deadline check between blocks (`SEARCH_EXECUTION_BUDGET_MS`, 50 ms per search invocation), and exceeding it aborts the run, returns the matches found so far, and emits `diagnostic { code: "search-budget-exceeded" }`. Because a catastrophic-backtracking pattern can still burn its whole budget inside a single `RegExp` call, search also caps the text one call sees (`SEARCH_REGEX_SEGMENT_MAX_CODE_UNITS`, 64 Ki code units per block segment); the per-block bound is the containment, and this bounds the worst-case main-thread stall rather than attempting regex complexity analysis.

## Retired

No `SEC` member is retired. SEC1–SEC9 are all live and govern shipped code.
