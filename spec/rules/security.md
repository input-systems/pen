# Security Rules

The `SEC` family is the complete security posture for the workspace: nothing security-relevant ships outside these rules. The attacker-controllable inputs are pasted clipboard content, imported content, AI and tool payloads, and the document itself; host-provided configuration such as custom schemas, renderers, and facet values is trusted, because hosts own their own code. Because any peer with write access can place arbitrary strings into block props, mark records, and inline-node props through a raw CRDT update that never passes `editor.apply` validation, the load-bearing boundary is render and interaction time rather than import time — importers exist to preserve fidelity, not to establish safety. Pen guarantees that rendering arbitrary written state is safe; it does not implement content encryption, access control, or a permission model, which belong to the host and the transport.

## SEC — security model

- SEC1. One module owns URL admission for everything the library renders: `urlPolicy` in `@input/pen-core` (`packages/core/src/security/urlPolicy.ts`), re-exported by `@input/pen-dom` so renderer hosts keep their import path, with the shape `resolve(rawValue: unknown, context: "link" | "image" | "media" | "download") => string | null` where `null` means inert. The default policy admits `http:`, `https:`, `mailto:`, and `tel:` plus relative and protocol-relative URLs, admits `data:image/(png|jpeg|gif|webp|avif)` in `image` context only, and returns `null` for everything else including `javascript:`, `vbscript:`, `file:`, `data:text/html`, unparsable values, and non-string values; admission parses with `new URL(value, "https://pen.invalid/")` and compares the parsed protocol, never a regex over the raw string. A `null` resolution renders the element without its URL-bearing attribute plus `data-pen-blocked-url=""`, and the raw URL is never echoed into the DOM, logs, or diagnostics beyond its scheme; every URL sink in library rendering and export goes through the policy, and hosts customize it through the single-value `pen.urlPolicy` facet, which receives the default policy to delegate to, so loosening to arbitrary schemes is possible but explicit.
- SEC2. No library code turns a string into markup. The `no-html-injection-sinks` lint runs unscoped across every linted file in the workspace and reports assignment to `innerHTML` or `outerHTML`, any use of `insertAdjacentHTML` or `Range.createContextualFragment`, `document.write` and `document.writeln`, and the `dangerouslySetInnerHTML` JSX attribute; reading `innerHTML` stays legal because assignment is the sink, and all rendering builds DOM through `createElement`, `textContent`, and attribute setters. Parsing untrusted HTML into a detached document with `DOMParser.parseFromString` is permitted because parsing is not injection, but the parsed tree's text and attributes only ever enter the document as data and are never re-serialized into live DOM; model output is text by construction, flowing through `TextStreamWriter.append` or ops, so no path exists by which it becomes markup. Any helper that applies an attribute bag to an element — `applyElementAttributes` in `@input/pen-dom`, which writes inline decoration attributes, is the one that matters — skips every key matching `/^on/i` and every key that lowercases to `style`, because event handlers and stylesheets are not data, and admits `href`, `src`, and `xlink:href` only through the URL policy, writing `data-pen-blocked-url=""` when admission fails. The discipline lives in the helper rather than in each caller's judgment, so a decoration that carries presentation in an inline `style` attribute has no effect and class hooks are the working contract for styling decorations.
- SEC3. HTML sanitization has exactly one owner, the `html` surface of `@input/pen-interop` (`packages/extensions/interop/src/html/import/sanitize.ts`), built on DOMPurify with an explicit tag and attribute allowlist, and no regex ever rewrites sanitized markup: filtering `style` down to `color` and `background-color` runs in a DOMPurify `uponSanitizeAttribute` hook, because regex post-processing of serialized HTML is how mutation XSS gets reintroduced. The config keeps `id` out of `ALLOWED_ATTR` because it is DOM-clobbering surface that conversion does not consume, and sets `ALLOW_DATA_ATTR: false` so no `data-*` wildcard becomes a markup-smuggling or exfiltration channel through round-trips. The paste path uses the same module — clipboard HTML goes `sanitizeHTML` → `DOMParser` → conversion — `@input/pen-dom` transfer code must not parse raw clipboard HTML itself, and the sanitizer is a direct dependency of the package that owns paste conversion (`@input/pen-preset-default`, which installs `html-clipboard`) rather than an optional peer, so it cannot be absent at runtime.
- SEC4. Copy writes `text/plain`, `text/html` (exporter-generated and escaped per SEC5), and `application/x-pen-blocks+json`; the older `application/x-pen-blocks` flavor may still be written so older readers keep working, and paste reads the current MIME first, then the legacy flavor. Pasted JSON and imported JSON documents are schema-validated before ops are built: block `type` must resolve in the registry, props are validated by the block's prop schema, unknown block types and unknown props are dropped with `diagnostic { code: "import-dropped" }`, and depth and node-count bounds are constants rather than options (nesting depth 32, 10,000 nodes per ingest, as `INGEST_MAX_NESTING_DEPTH`/`INGEST_MAX_NODE_COUNT` and their clipboard counterparts, which add a 1 MiB text cap and a 256-image cap). Every ingest path carries the same bound set rather than JSON alone — the JSON, HTML, Markdown, and XML surfaces of `@input/pen-interop` and the `@input/pen-dom` clipboard path each own named constants — and a drop caused by a bound reports `diagnostic { code: "import-truncated" }` to distinguish a size refusal from a content refusal. `__proto__`, `constructor`, and `prototype` are rejected as own keys anywhere in ingested JSON — props, marks, and metadata — ingestion builds fresh null-prototype records during validation rather than deep-merging raw parsed JSON into existing objects, and URL-bearing props are not pre-laundered: they pass through SEC1 at render time like everything else, so a policy change applies retroactively to stored content.
- SEC5. Exporters — the XML and HTML surfaces of `@input/pen-interop`, the HTML clipboard flavor, and any `toHTML` path — construct output through a serializer that escapes text nodes and attribute values (`&`, `<`, `>`, `"`, `'`), and interpolating unescaped document content into markup is banned by the `no-unescaped-markup-concat` lint over `packages/extensions/interop/src`, `packages/schema/default/src`, and the two `@input/pen-dom` clipboard serializers (`utils/clipboardSerialization.ts` and `utils/tableCellClipboard.ts`), which admits an interpolation only when it passes an escaping or serializing call, is already-serialized inner HTML, or is justified by an adjacent comment naming SEC5. Despite its name that lint inspects markup template literals only, so `+` concatenation into markup is not reported: the escaping obligation is the rule, and the lint covers the shape this codebase writes rather than the full obligation. The scope includes the block and inline `toHTML` serializers in `packages/schema/default`, whose sinks are attribute interpolations rather than text nodes (`href` on link marks, color values into `style`, image `src`, inline-node `data-id`, `class="language-…"` on code blocks): serializers receive the escaping helper (`packages/schema/default/src/escapeHtml.ts`) or emit structured nodes the exporter serializes, and never concatenate raw prop values into attribute positions. Export → sanitize → import is a round-trip property: a document carrying hostile-corpus strings as plain text yields the same plain text back with zero markup execution, and a document whose `href`, color, `lang`, or `data-id` props contain attribute-breakout strings exports to HTML that parses back with those values as attribute data and zero new elements or handlers.
- SEC6. `@input/pen-document-ops` validates tool-call payloads structurally before building ops: the op `type` must be a known member of the `DocumentOp` union, targets must resolve, and string fields are capped by a constant (`MAX_OP_TEXT_FIELD_LENGTH`, 1 MiB per op text field); an invalid payload produces diagnostics and no partial application. Ops arriving from any source cannot smuggle non-validated shapes past the pipeline's validate phase, whose unknown-type drop is the enforcement point and whose diagnostics are the audit trail. Op executors never spread raw payload objects into CRDT writes: the validate phase applies the same `__proto__`/`constructor`/`prototype` own-key rejection as SEC4, and executors build fresh records from validated fields.
- SEC7. Dependencies that process untrusted input are limited to the sanitizer (DOMPurify via `isomorphic-dompurify`), whose version range is pinned tighter than the rest of the tree (`~3.22.0`, a patch range rather than a caret) so a security-relevant minor or major cannot arrive unreviewed; adding another such dependency amends this rule. No published package may declare an install script — `preinstall` and `postinstall` are banned, checked by `scripts/no-install-scripts.mjs` — `pnpm audit --prod` runs in CI as a report and blocks a release cut on critical advisories in runtime dependencies, and dependency-update automation covering the workspace and its GitHub Actions, `dependency-review` on pull requests, and CodeQL or an equivalent SAST on the default branch keep a small dependency surface current rather than merely small. `SECURITY.md` carries the private disclosure channel, a 90-day coordinated-disclosure default, a supported-versions table, and a commitment to publish advisories for anything reachable through the SEC1–SEC6 surfaces; npm provenance (API7) is the control that makes those claims verifiable from outside the repository.
- SEC8. The library executes no dynamic code: `eval`, `new Function`, and string-bodied `setTimeout`/`setInterval` are banned by lint across all packages (`no-eval`, `no-new-func`, `no-implied-eval` in `eslint.config.mjs`), and Pen must be fully functional under `script-src 'self'`. Inline `style` attributes are used only for geometry-derived positioning such as overlay transforms and everything else is class-based, so a host running `style-src` without `'unsafe-inline'` loses only overlays; a strict-CSP conformance scenario documents exactly what degrades.
- SEC9. `@input/pen-search` treats a user-supplied regex as hostile input: `regex: false` is the default, query length is capped by a constant (`SEARCH_QUERY_MAX_LENGTH`, 1,024 characters), and a pattern compiles with the `u` flag inside a `try`/`catch` that surfaces an invalid pattern as a diagnostic rather than a throw. Regex execution runs under a budget: matching proceeds block by block with a deadline check between blocks (`SEARCH_EXECUTION_BUDGET_MS`, 50 ms per search invocation), and exceeding it aborts the run, returns the matches found so far, and emits `diagnostic { code: "search-budget-exceeded" }`. Because a catastrophic-backtracking pattern can still burn its whole budget inside a single `RegExp` call, search also caps the text one call sees (`SEARCH_REGEX_SEGMENT_MAX_CODE_UNITS`, 64 Ki code units per block segment); the per-block bound is the containment, and this bounds the worst-case main-thread stall rather than attempting regex complexity analysis.

## Retired

No `SEC` member is retired. SEC1–SEC9 are all live and govern shipped code.
