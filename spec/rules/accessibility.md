# Accessibility Rules

The `AX` family targets WCAG 2.2 AA for everything Pen itself renders, and requires that the primitives a host composes make AA achievable without fighting the library. Accessibility cannot be bolted onto an editor by its host, because the editing surface, the focus model, and live updates are all library-owned. Surface semantics, the announcer, the focus sink, and the reduced-motion signal live in `packages/rendering/dom/src/a11y/`; every announcement string resolves through the message catalog specified in `spec/rules/localization.md`; the overlay chrome these rules classify as presentation is specified in `spec/rules/dom.md` and `spec/rules/selection.md`. Pen ships no high-contrast theme, no braille-specific behavior beyond correct semantics, no automatic alt text, and no spellcheck or grammar semantics: AX5 is what keeps a host theme buildable, and the schema `a11y.label` seam in AX4 is where a host or a model plugs in image descriptions.

## AX — accessibility

- AX1. The editor content root carries `role="textbox"` and `aria-multiline="true"`, plus an `aria-label` or `aria-labelledby` resolved from the single-value `pen.a11yLabel` facet by `resolveEditorA11yLabel`; `mountEditor`, React `EditorRoot`, and Vue `PenEditor` all emit that set. The root is the editor's single tab stop while focus is outside it and leaves the tab order while the editor owns focus, so native Tab and Shift-Tab traversal cannot land on both the active surface and its root. A contenteditable surface carries `tabindex="0"` only while it owns focus and drops back to `-1` on blur: Firefox does not Shift-Tab out of a focused contenteditable with `tabindex="-1"`, and a surface that stayed at `0` after focus left would sit in the tab order beside its root. An EditContext surface keeps `tabindex="-1"`, which it needs to be focusable at all. Direct keyboard focus restores a same-block text selection, activates the first inline text field at offset zero when no selection exists, or transfers a block or cell selection, or a text range in an S2 exception state, to its revealed focus sink; other selections remain on the root, as does a read-only root unless it owns a block or cell selection. A host is expected to supply the label, and a missing one is diagnosed as `a11y-missing-label`, but the diagnostic fires at most once per editor and only when a `diagnostic` listener is already attached at the moment a surface first resolves the label; the root then falls back to the `pen.editor.label` catalog string, so an unlabeled host degrades to a generic name rather than to silence. The `pen.ariaReadOnly` facet is reflected as `aria-readonly="true"` and is an ARIA hint only: it does not decline input, does not stop `editor.apply`, and does not gate the collaboration wire. The renderer `readonly` prop is the single input control, so a host that sets only the facet ships a surface which announces itself read-only and still accepts keystrokes; that split is intended, and the facet name is what keeps it honest. Block structure conveys itself through native elements wherever one exists — headings as `h1` through `h6`, quotes as `blockquote`, code as `pre` wrapping `code`, tables as `table` with `scope="col"` header cells, callouts as `role="note"` — and custom semantics never replace an available native element. List items keep their document model and gain their semantics at render time: `bulletListItem`, `numberedListItem`, and `checkListItem` stay independent blocks with a decorative `aria-hidden` marker, and each binding — React `EditorContent` and `Pen.Editor.BlockChildren`, Vue `PenContent` and `PenBlock`, and `mountEditor` — wraps every run of consecutive list items in a sibling list in a `div[data-pen-list-group]` with `role="list"`, putting `role="listitem"`, `aria-level` (indent plus one), `aria-posinset`, and `aria-setsize` on the item's block host. The grouping is computed by `getListSegments` and `getListItemSemantics` in `@input/pen-core` over the same sibling list the renderer iterates, so positions are the model's and stay correct when only part of a run is mounted. A run ends at any other block, and a top-level item of a different list type starts a new list; a set is the items of one level that share their nearest shallower item, and ends where two consecutive same-level items differ in type. `div`s rather than `ul`, `ol`, and `li` keep native contenteditable list editing out of the field, and the attributes sit on the block host rather than on `ListItemLayout`, so HB8's write order is unaffected. An item that moves between groups when a run splits or merges is remounted by React and Vue (moved, never recreated, by `mountEditor`), and the field re-attaches through its keyed mount acknowledgement; a numbered item's visual marker — `getNumberedListItemValue` in `@input/pen-core`, the notifier's `ordinal` — counts over that same sibling list: the consecutive numbered items before it at its indent, back to a shallower item or any other block, from the nearest `start`, so blocks nested under an earlier sibling never continue its count and a numbered item after a blockquote holding numbered children starts at 1, matching the list it is announced in. The marker can still differ from `aria-posinset` when `start` is set, because assistive technology announces the position in the set. The hidden focus sink (`packages/rendering/dom/src/a11y/focusSink.ts`) is `aria-hidden="true"` and out of the tab order under a text, app, or null selection, and `syncFocusSink` reveals it for a block or cell selection and for a text selection in an S2 exception state by removing `aria-hidden`, setting `tabIndex` to 0, applying `role="group"` for a block selection or a text range or `role="grid"` for a cell selection, and labeling it from the matching catalog entry (`pen.a11y.textRangeSelected` with the range's block count for a text range). Construction clip-hides the sink with the same visually-hidden recipe as the AX2 live region, so a host `:focus-visible` rule cannot paint a ring on it when the reveal moves focus onto it; the sink is never a visual surface, and block and cell selection stay visible through the AX7 overlay. When that selection is revealed, `syncFocusSink` also moves DOM focus onto the sink in the same turn if the editor already owns focus or focus has fallen to the document body (HOST9); it does not steal from a native control outside the editor. S4 forbids a deferred focus restore.
- AX2. Each editor root owns exactly one visually-hidden live region (`role="status"`, `aria-live="polite"`, `aria-atomic="true"`) created by `createAnnouncer()` in `packages/rendering/dom/src/a11y/announcer.ts`, whose surface is `announce(message, priority?, key?)` with a priority of `"polite"` or `"assertive"`. It is the only `aria-live` region in library production code; scattered live-region islands are banned because they double-announce against the central queue. Every announcement string comes from the single-value `pen.messages` facet under the `pen.a11y.*` keys typed by `A11yMessageKey`, with English defaults exported for hosts to override, so the library hardcodes no user-facing announcement text outside that catalog. `bindEditorAnnouncer` subscribes the region to commit, history, and selection events and covers block type conversion, undo and redo with a block-type hint, entering and changing a block selection with a count, cell selection dimensions, and atom selection; extensions announce through `announceEditorA11y` in `@input/pen-core` so they need no dependency on `@input/pen-dom`, which is how search contributes find-match counts, `@input/pen-ai` contributes suggestion appeared, accepted, and rejected along with streaming started and finished, and multiplayer contributes collaborator joined and editing. Announcements are rate-limited per key at one per 500 milliseconds (`ANNOUNCE_RATE_LIMIT_MS`) with the latest pending message winning, so streaming and rapid selection growth cannot flood the queue. Each announcement is one write job queued in the root's `DomScheduler` write phase (the region's aria-live token and text change together in that job), while the region itself is created synchronously, because a live region must exist before its first change for assistive technology to track it; the per-key rate limit is stamped when the job is queued, so a burst inside the window still yields the latest message once.
- AX3. Popups anchored to the caret keep DOM focus in the editing field, which is what lets IME keep working, and navigate through `aria-activedescendant`: the popup is a `role="listbox"` or `role="menu"` owning its option IDs, ArrowUp, ArrowDown, Home, and End move the active option, Enter and Tab accept, Escape closes and returns the surface to plain typing, and the field carries `aria-controls` and `aria-expanded` while the popup is open. The shipped React surfaces on that pattern are the slash menu, the suggestion menu, and the AI suggestions popover; the AI command menu is a combobox that takes focus into its own filter input while open and returns it on close. A closed list is `hidden` and drops its `role` so assistive technology never encounters an empty listbox. Detached surfaces use roving `tabindex` with arrow-key navigation inside and close on Escape, the shipped instances being the block handle menu and the renderer-owned table column header menu. Every interactive primitive is reachable without a pointer: the block handle opens its menu on Enter or Space and offers reordering as menu items dispatching `pen.moveBlockUp` and `pen.moveBlockDown` so drag-only reordering always has a keyboard path, and table row and column insertion are keyboard-activatable renderer buttons. No primitive traps focus except an explicit dialog, and a dialog returns focus to its invoker on close. Focus returns by primitive class, following the WAI-ARIA Authoring Practices, synchronously and never through a timer. Caret-anchored popups never take focus, so the field still has it after accept or Escape. A toolbar never takes focus from a pointer, keeps focus on a control activated from the keyboard, as a toolbar should, and returns it to the editor on Escape; the floating selection toolbar does the same, and when an action unmounts it with the selection, focus returns to the editor. Detached menus and dialogs return focus to their invoker, unless the action removed that control, in which case focus goes to the editor surface at the resulting selection — the active field, or the focus sink for a block or cell selection. A block handle menu move that regroups a list item remounts the block and its handle (AX1); the remounted handle is the invoker, and focus returns to it in the same commit. Popovers that take focus into their own input — the AI command menu and the AI contextual prompt — return it on accept, reject, dismiss, and Escape to whatever held it when they opened. No return steals focus from a native text-entry control that took it meanwhile (HOST9). There is no library link-editor primitive and no emoji picker, so a host owns those popovers and owes them this contract itself; Vue ships the editing surface only, so the popup and menu half of this rule has no Vue subject.
- AX4. A block or inline schema may declare an optional `a11y` spec through `defineBlock(...).a11y` — a `label(props)` function plus an optional `roleDescription` — and `resolveSchemaA11y` applies it to atom and widget host elements as an accessible name, adding `aria-roledescription` when a role description is provided. An atom without a label falls back to its type name and emits an `a11y-missing-label` diagnostic once per type per session when a diagnostic listener is attached; the default schema labels `mention`, `inlineApp`, and `image`, so that fallback is a signal to schema authors rather than a normal path. A `contenteditable="false"` atom host must remain in the accessibility tree, so `aria-hidden` on visible content is banned across `packages/rendering/**` by the `pen/no-aria-hidden-visible` ESLint rule, and an exception must carry an adjacent comment naming AX7, the focus sink, or an explicit justification, which is how decorative list markers and overlay chrome stay legal. Caret interaction with an atom announces the resolved label under the `atomSelected` key, but only for a collapsed caret resting at an atom-adjacent offset: the announcement path returns early for a non-collapsed selection, so selecting an atom as a range does not announce it.
- AX5. The library never removes focus indication: any `outline: none` Pen emits must be accompanied by a `:focus-visible` replacement in the same rule set, enforced across `packages/rendering/**` by the `pen/no-unstyled-focus` ESLint rule. `PEN_EDITOR_CHROME_STYLESHEET` is the production site that sets `outline: none` on the editor surfaces, and it restores a ring on `[data-pen-inline-content]:focus-visible` via `--pen-focus-ring` (default `Highlight`). Overlay carets and selection highlights are decorative duplicates of state that is also conveyed non-visually through the AX2 announcements and, inside the active field, through the native selection; they never become the only signal on the default sheet. A host that sets `--pen-focus-ring: transparent` — a playground or product that already paints a caret — owns a replacement. Information must not be encoded in color alone. The rendering packages contain no `.css` files; chrome and review ship as exported text (API7). This constraint also binds the style objects the renderers emit inline, and the worked examples of host taste — a block-selection background and suggestion states drawn as underline styles plus icons — live in the playground and conformance reference styles rather than in a library theme. The block-selection outline itself is drawn by the library (O3) through `--pen-block-selection-outline`, an inset 2px `Highlight` ring by default that a host may set to `none`, because a selection nobody can see is a correctness failure under HOST6 rather than a matter of taste.
- AX6. Library-owned animation respects `prefers-reduced-motion: reduce` through one central signal, `createReducedMotionSignal()` in `packages/rendering/dom/src/a11y/motion.ts`, which is the only site in library code permitted to name that media query; per-feature media queries are banned so the behavior cannot drift, a conformance scenario enforces the single site by grep, and a missing `matchMedia` degrades to `reduced: false` rather than throwing. The intended mapping is recorded as `AX6_MOTION_MAPPING`: caret blink becomes a solid caret, streaming shimmer becomes a static badge, and transitions become instant. The caret mapping is implemented in `@input/pen-dom`'s overlay controller, which reads the signal once per root and paints every overlay caret with `animation: none` while it is set, so a host-supplied `--pen-editor-caret-animation` cannot reintroduce a blink under reduced motion. Blink restarts are keyed element replacements rather than a timer, so reduced motion has no pause state to unify with. Each editor root has one shared signal, `getRootReducedMotion(root)`, which the overlay, the root attribute and bindings all read. The transition mapping is implemented by reflecting that signal as a presence-only `data-pen-reduced-motion` attribute on the editor root, written in the overlay's write phase. The library's one transition, the AI suggestion underline, reads it to turn itself off, and hosts may select on it too. React hosts read the same value through `useReducedMotion`, and `AX6_MOTION_MAPPING`, `REDUCED_MOTION_ATTR` and `getRootReducedMotion` are exported from `@input/pen-dom`. The library ships no shimmer, drag-preview transition, or animated collapse, so those mappings bind host code rather than library code.
- AX7. Overlay chrome is presentation and never the accessible representation of anything: remote carets, selection rectangles, the library caret, drag previews, and drop indicators are all `aria-hidden="true"` with `pointer-events: none`, and remote collaborator presence reaches assistive technology through the rate-limited `collaboratorJoined` and `collaboratorEditing` announcements and through host-composed presence UI instead. Enforcement is both by containment and per primitive. `@input/pen-dom` creates one `data-pen-overlay-layer` element per editor root (OV2) and sets `aria-hidden` and `pointer-events: none` on it and on every item it paints, as inline values, so a binding portal or a host stylesheet cannot drop them. React primitives that still render outside the layer — the drag overlay and the region marquee — set both properties themselves, forced after `asChild`; remote collaborator carets and their name labels are layer items (OV3). Drop targeting is the clearest case of that dispersal, marking live blocks with `data-drop-target` and rendering an inline `data-pen-drop-caret`, neither of which sits in an overlay layer, with the caret carrying its own `aria-hidden`.
- AX8. Screen-reader behavior cannot be fully automated, so a manual assistive-technology matrix is the release-train obligation: VoiceOver with Safari on macOS and iOS, NVDA with Chrome and with Firefox on Windows, and TalkBack with Chrome on Android, each row running the same five scripted scenarios — read-through of a fixture document with headings, lists, tables, and atoms announced correctly, typing echo, selection announcements, popup navigation, and the suggestion accept flow. JAWS is informational. A row may not be marked complete without a dated pass recording tester, platform, and versions, and completing the VoiceOver and NVDA rows is that obligation; no release workflow reads the matrix, so it does not block a release cut, and it is not a per-pull-request gate. The committed checklist at `packages/rendering/dom/src/a11y/MANUAL.md` is a stub: every row is incomplete and no assistive-technology session has been recorded, which makes this the one `AX` rule whose gate has never run. The automated floor underneath it does run, and axe-core executes the WCAG 2.2 AA rule set against the editor root after every conformance scenario and across the fixture set on Chromium with zero violations blocking, alongside dedicated scenarios for surface semantics, keyboard-only operation, and reduced motion.

## Retired

No `AX` member is retired. AX1 through AX8 all govern shipped code.

- The `pen.readOnly` facet name is retired in favor of `pen.ariaReadOnly` (`readOnlyFacet` became `ariaReadOnlyFacet`), because the old name promised an edit gate the facet never implemented. AX1 states what it does own.
- The two ad-hoc `aria-live` regions that lived in the React selection-rect primitive are deleted, superseded by the single AX2 announcer.
