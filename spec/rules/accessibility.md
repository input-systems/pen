# Accessibility Rules

The `AX` family targets WCAG 2.2 AA for everything Pen itself renders, and requires that the primitives a host composes make AA achievable without fighting the library. Accessibility cannot be bolted onto an editor by its host, because the editing surface, the focus model, and live updates are all library-owned. Surface semantics, the announcer, the focus sink, and the reduced-motion signal live in `packages/rendering/dom/src/a11y/`; every announcement string resolves through the message catalog specified in `spec/rules/localization.md`; the overlay chrome these rules classify as presentation is specified in `spec/rules/dom.md` and `spec/rules/selection.md`. Pen ships no high-contrast theme, no braille-specific behavior beyond correct semantics, no automatic alt text, and no spellcheck or grammar semantics: AX5 is what keeps a host theme buildable, and the schema `a11y.label` seam in AX4 is where a host or a model plugs in image descriptions.

## AX — accessibility

- AX1. The editor content root carries `role="textbox"` and `aria-multiline="true"`, plus an `aria-label` or `aria-labelledby` resolved from the single-value `pen.a11yLabel` facet by `resolveEditorA11yLabel`; `mountEditor`, React `EditorRoot`, and Vue `PenEditor` all emit that set. The root is the editor's single tab stop while focus is outside it and leaves the tab order while the editor owns focus, so native Tab and Shift-Tab traversal cannot land on both the active surface and its root. Direct keyboard focus restores a same-block text selection, activates the first inline text field at offset zero when no selection exists, or transfers a block or cell selection to its revealed focus sink; other selections remain on the root, as does a read-only root unless it owns a block or cell selection. A host is expected to supply the label, and a missing one is diagnosed as `a11y-missing-label`, but the diagnostic fires at most once per editor and only when a `diagnostic` listener is already attached at the moment a surface first resolves the label; the root then falls back to the `pen.editor.label` catalog string, so an unlabeled host degrades to a generic name rather than to silence. The `pen.ariaReadOnly` facet is reflected as `aria-readonly="true"` and is an ARIA hint only: it does not decline input, does not stop `editor.apply`, and does not gate the collaboration wire. The renderer `readonly` prop is the single input control, so a host that sets only the facet ships a surface which announces itself read-only and still accepts keystrokes; that split is intended, and the facet name is what keeps it honest. Block structure conveys itself through native elements wherever one exists — headings as `h1` through `h6`, quotes as `blockquote`, code as `pre` wrapping `code`, tables as `table` with `scope="col"` header cells, callouts as `role="note"` — and custom semantics never replace an available native element. List items are the deliberate exception: `bulletListItem`, `numberedListItem`, and `checkListItem` each render as an independent block with a decorative `aria-hidden` marker rather than as `ul`, `ol`, and `li`, because every item is its own block and wrapping runs in a list parent would invent a container the document model does not have. The hidden focus sink (`packages/rendering/dom/src/a11y/focusSink.ts`) is `aria-hidden="true"` and out of the tab order under a text, app, or null selection, and `syncFocusSink` reveals it for a block or cell selection by removing `aria-hidden`, setting `tabIndex` to 0, applying `role="group"` for a block selection or `role="grid"` for a cell selection, and labeling it from the matching catalog entry. Construction clip-hides the sink with the same visually-hidden recipe as the AX2 live region, so a host `:focus-visible` rule cannot paint a ring on it when the reveal moves focus onto it; the sink is never a visual surface, and block and cell selection stay visible through the AX7 overlay. When that selection is revealed, `syncFocusSink` also moves DOM focus onto the sink in the same turn if the editor already owns focus or focus has fallen to the document body (HOST9); it does not steal from a native control outside the editor. S4 forbids a deferred focus restore.
- AX2. Each editor root owns exactly one visually-hidden live region (`role="status"`, `aria-live="polite"`, `aria-atomic="true"`) created by `createAnnouncer()` in `packages/rendering/dom/src/a11y/announcer.ts`, whose surface is `announce(message, priority?, key?)` with a priority of `"polite"` or `"assertive"`. It is the only `aria-live` region in library production code; scattered live-region islands are banned because they double-announce against the central queue. Every announcement string comes from the single-value `pen.messages` facet under the `pen.a11y.*` keys typed by `A11yMessageKey`, with English defaults exported for hosts to override, so the library hardcodes no user-facing announcement text outside that catalog. `bindEditorAnnouncer` subscribes the region to commit, history, and selection events and covers block type conversion, undo and redo with a block-type hint, entering and changing a block selection with a count, cell selection dimensions, and atom selection; extensions announce through `announceEditorA11y` in `@input/pen-core` so they need no dependency on `@input/pen-dom`, which is how search contributes find-match counts, `@input/pen-ai` contributes suggestion appeared, accepted, and rejected along with streaming started and finished, and multiplayer contributes collaborator joined and editing. Announcements are rate-limited per key at one per 500 milliseconds (`ANNOUNCE_RATE_LIMIT_MS`) with the latest pending message winning, so streaming and rapid selection growth cannot flood the queue. The region write is still a direct synchronous DOM write rather than one scheduled through `DomScheduler`; the call sites are marked for that conversion, and until it lands the announcer is the one accessibility path writing outside the flush contract in `spec/rules/dom.md`.
- AX3. Popups anchored to the caret keep DOM focus in the editing field, which is what lets IME keep working, and navigate through `aria-activedescendant`: the popup is a `role="listbox"` or `role="menu"` owning its option IDs, ArrowUp, ArrowDown, Home, and End move the active option, Enter and Tab accept, Escape closes and returns the surface to plain typing, and the field carries `aria-controls` and `aria-expanded` while the popup is open. The shipped React surfaces on that pattern are the slash menu, the suggestion menu, the AI command menu, and the AI suggestions popover; a closed list is `hidden` and drops its `role` so assistive technology never encounters an empty listbox. Detached surfaces use roving `tabindex` with arrow-key navigation inside and close on Escape, the shipped instances being the block handle menu and the renderer-owned table column header menu. Every interactive primitive is reachable without a pointer: the block handle opens its menu on Enter or Space and offers reordering as menu items dispatching `pen.moveBlockUp` and `pen.moveBlockDown` so drag-only reordering always has a keyboard path, and table row and column insertion are keyboard-activatable renderer buttons. No primitive traps focus except an explicit dialog, and a dialog restores focus on close. Two limits are real rather than stylistic. After an action that mutates the document, focus returns to the editor surface but not yet to the invoking control, because that restoration depends on selection re-projection having run. There is no library link-editor primitive and no emoji picker, so a host owns those popovers and owes them this contract itself; Vue ships the editing surface only, so the popup and menu half of this rule has no Vue subject.
- AX4. A block or inline schema may declare an optional `a11y` spec through `defineBlock(...).a11y` — a `label(props)` function plus an optional `roleDescription` — and `resolveSchemaA11y` applies it to atom and widget host elements as an accessible name, adding `aria-roledescription` when a role description is provided. An atom without a label falls back to its type name and emits an `a11y-missing-label` diagnostic once per type per session when a diagnostic listener is attached; the default schema labels `mention`, `inlineApp`, and `image`, so that fallback is a signal to schema authors rather than a normal path. A `contenteditable="false"` atom host must remain in the accessibility tree, so `aria-hidden` on visible content is banned across `packages/rendering/**` by the `pen/no-aria-hidden-visible` ESLint rule, and an exception must carry an adjacent comment naming AX7, the focus sink, or an explicit justification, which is how decorative list markers and overlay chrome stay legal. Caret interaction with an atom announces the resolved label under the `atomSelected` key, but only for a collapsed caret resting at an atom-adjacent offset: the announcement path returns early for a non-collapsed selection, so selecting an atom as a range does not announce it.
- AX5. The library never removes focus indication: any `outline: none` Pen emits must be accompanied by a `:focus-visible` replacement in the same rule set, enforced across `packages/rendering/**` by the `pen/no-unstyled-focus` ESLint rule. `PEN_EDITOR_CHROME_STYLESHEET` is the production site that sets `outline: none` on the editor surfaces, and it restores a ring on `[data-pen-inline-content]:focus-visible` via `--pen-focus-ring` (default `Highlight`). Overlay carets and selection highlights are decorative duplicates of state that is also conveyed non-visually through the AX2 announcements and, inside the active field, through the native selection; they never become the only signal on the default sheet. A host that sets `--pen-focus-ring: transparent` — a playground or product that already paints a caret — owns a replacement. Information must not be encoded in color alone. The rendering packages contain no `.css` files; chrome and review ship as exported text (API7). This constraint also binds the style objects the renderers emit inline, and the worked examples of host taste — block selection drawn as an outline plus a background and suggestion states drawn as underline styles plus icons — live in the playground and conformance reference styles rather than in a library theme.
- AX6. Library-owned animation respects `prefers-reduced-motion: reduce` through one central signal, `createReducedMotionSignal()` in `packages/rendering/dom/src/a11y/motion.ts`, which is the only site in library code permitted to name that media query; per-feature media queries are banned so the behavior cannot drift, a conformance scenario enforces the single site by grep, and a missing `matchMedia` degrades to `reduced: false` rather than throwing. The intended mapping is recorded as `AX6_MOTION_MAPPING`: caret blink becomes a solid caret, streaming shimmer becomes a static badge, and transitions become instant. Only the caret mapping is implemented. The React caret overlay subscribes to the signal and unifies reduced motion with the type-pause behind a single `solidCaret` parameter, which is also why a host-supplied `--pen-editor-caret-animation` token cannot reintroduce a blink under reduced motion. The shimmer and transition mappings have no consumer: streaming indicators, drag preview transitions, and toggle collapse and expand do not read the signal yet.
- AX7. Overlay chrome is presentation and never the accessible representation of anything: remote carets, selection rectangles, the library caret, drag previews, and drop indicators are all `aria-hidden="true"` with `pointer-events: none`, and remote collaborator presence reaches assistive technology through the rate-limited `collaboratorJoined` and `collaboratorEditing` announcements and through host-composed presence UI instead. Enforcement is per primitive rather than by containment. The `data-pen-overlay-layer` element this rule was originally written against is mounted only by the conformance harness; no shipped renderer creates a single overlay layer, so each React overlay primitive — the caret overlay, the multiplayer caret overlay, the selection rectangle, and the drag overlay — sets both properties itself, forced after `asChild` so host styling cannot drop them. Drop targeting is the clearest case of that dispersal, marking live blocks with `data-drop-target` and rendering an inline `data-pen-drop-caret`, neither of which sits in an overlay layer, with the caret carrying its own `aria-hidden`.
- AX8. Screen-reader behavior cannot be fully automated, so a manual assistive-technology matrix gates a release cut: VoiceOver with Safari on macOS and iOS, NVDA with Chrome and with Firefox on Windows, and TalkBack with Chrome on Android, each row running the same five scripted scenarios — read-through of a fixture document with headings, lists, tables, and atoms announced correctly, typing echo, selection announcements, popup navigation, and the suggestion accept flow. JAWS is informational. A row may not be marked complete without a dated pass recording tester, platform, and versions, and completing the VoiceOver and NVDA rows is a release-train obligation rather than a per-pull-request gate. The committed checklist at `packages/rendering/dom/src/a11y/MANUAL.md` is a stub: every row is incomplete and no assistive-technology session has been recorded, which makes this the one `AX` rule whose gate has never run. The automated floor underneath it does run, and axe-core executes the WCAG 2.2 AA rule set against the editor root after every conformance scenario and across the fixture set on Chromium with zero violations blocking, alongside dedicated scenarios for surface semantics, keyboard-only operation, and reduced motion.

## Retired

No `AX` member is retired. AX1 through AX8 all govern shipped code.

- The `pen.readOnly` facet name is retired in favor of `pen.ariaReadOnly` (`readOnlyFacet` became `ariaReadOnlyFacet`), because the old name promised an edit gate the facet never implemented. AX1 states what it does own.
- The two ad-hoc `aria-live` regions that lived in the React selection-rect primitive are deleted, superseded by the single AX2 announcer.
